# Data rights

> **Engineering template — not legal advice and not a compliance claim.**
> Drafted for an operator and their counsel to adapt. Installing Zi does not make
> any deployment compliant with any law. Review before production use.

The `privacy-controls` skill implements the behavior below. This file records what an
operator must be able to honor and how each is served.

| Right | How a person exercises it | What must happen |
|---|---|---|
| Transparency | asks what Zi does | plain description, no evasion |
| Access | "what do you remember about me?" | actual stored items, with provenance and dates |
| Correction | "that's wrong" | corrected immediately, old value not retained |
| Export | "export my data" | readable file: memory, preferences, consents, actions |
| Deletion | "delete my Zi data" | items plus derived personal material removed |
| Withdraw consent | "stop personalization" | immediate; Zi remains fully usable |
| Object to processing | "stop using my messages" | honored; state any consequence |
| Human contact | "talk to a human" | routed to a named human |
| Complaint | asks to escalate | given the operator's escalation path |

## Requirements

No friction: no reason required, no forms, no delay, no "are you sure" beyond a
single scope check. Recognize intent in any phrasing and any language.

Deletion covers derived material — preferences, segmentation, recommendation state,
personal notes inside summaries — not only the obvious record.

State what remains and why. Minimal audit that a consent was given and withdrawn is
usually legitimate; say so rather than implying total erasure.

State what is out of reach: messages already in a group, a calendar entry on someone's
device, anything already sent through a connector. Name who can help with those.

Record consents where the operator's jurisdiction requires it.
