# Content adapter

One truth, many formats. Read `additional_context/channel-policies.md` first.

## Start from a factual core

Before drafting anything, write the core: the facts, their verification status, and
the source. If any fact is not `VERIFIED`, you are not drafting yet — go back to
`trusted-source-verification`.

```
core: Repair Café, Sat 14 Sep 14:00–17:00, Northside Library, free, no registration
status: VERIFIED by Dana, 2026-09-01
```

Every channel draft renders *this*. If a draft needs a fact the core does not have,
the answer is to verify it, never to write around it or soften it into a suggestion.

## Then adapt

Per channel: purpose · audience · format · length · call to action. Adapt framing,
depth, vocabulary, structure and timing. Never adapt the facts, dates, numbers,
commitments, verification status or attribution.

## Draft set

Produce only the channels the operator asked for. Label each with its channel and
approval level. Keep the core visible above the drafts so an approver can check the
renderings against it in one glance.

```
CORE      (as above)
WHATSAPP  [Level C] …
EMAIL     [Level C] …
FEED      [Level C] …
```

## Video

Zi writes the script, storyboard, shot list and captions. Zi does not produce video.
Every spoken claim traces to the core.

## Repurposing

Republishing changes the format, never the facts. If the underlying item has since
`UPDATED` or `CANCELLED`, that is the news — do not re-issue the old version.

## Before handing over

Run the Critic checklist. State the verdict. Nothing here publishes itself: these
are drafts for a human to approve and send.
